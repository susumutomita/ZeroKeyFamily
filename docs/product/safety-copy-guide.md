# 安全文言ガイド

画面文言・通知・サポート回答・販促表現の正本。すべての文言は [Trust Claims](./trust-claims.md) に反してはならない。文言の追加・変更は本ガイドとの整合レビューを通す。

正本 Issue: https://github.com/susumutomita/ZeroKeyFamily/issues/3

## 原則

1. 検証した事実だけを言う。検証したのは「登録端末の署名」であり、「本人」「安全」ではない。
2. 確認できていない状態を、安心情報として表現しない。「応答なし」は成功でも失敗でもなく「未確認」である。
3. 高齢者が一読で理解できる語彙を使う。専門用語（署名・nonce・失効）は画面の主文に出さず、出す場合は言い換えを併記する。
4. 行動の指示を曖昧にしない。「ご注意ください」ではなく「お金を送らないでください」と書く。
5. 急かさない。期限・緊急の表示でユーザーの判断を圧迫しない。

## 状態別の標準文言

| 状態 | 標準文言（主文） | 禁止する文言 |
| --- | --- | --- |
| 確認済み | 「太郎さんの登録端末が、この内容に同意の署名をしました。」 | 「本人確認が完了しました」「ご本人です」「安全です」 |
| 拒否 | 「太郎さんの端末がこの内容を『身に覚えがない』と回答しました。お金を送らないでください。」 | 「失敗しました」（拒否は失敗ではなく重要情報） |
| 応答なし | 「まだ確認できていません。応答がないことは、相手が本人であることの確認にはなりません。」 | 「問題は見つかりませんでした」「しばらくお待ちください」のみで終える文 |
| 期限切れ | 「期限までに確認できませんでした。お金を送らないでください。」 | 「タイムアウトしました」（意味が伝わらない） |
| 検証失敗 | 「応答の検証に失敗しました。安全のため、承認として扱いません。」 | 「エラーが発生しました」のみで終える文 |
| 通信断 | 「インターネットに接続できていないため、確認の状態がわかりません。確認できるまで、お金を送らないでください。」 | 「オフラインです」のみで終える文 |

## 用語の言い換え表

| 内部用語 | 画面で使う表現 |
| --- | --- |
| 署名 | 「（人名）さんの端末による同意」 |
| 検証 | 「確認」 |
| 失効 | 「この端末を使えなくする」 |
| Trust Circle | 「家族グループ」 |
| 確認要求 | 「確認のお願い」 |
| nonce / リプレイ | 画面に出さない |

## 「確認済み」表示の必須要素

「確認済み」を表示する画面には、次の 3 点を必ず併記する。

1. 誰の登録端末が署名したか（「太郎さんの登録端末が」）。
2. 何に署名したか（金額・送金先・理由の再掲）。
3. 限界の注意（「これは端末の署名の確認です。少しでも不安があれば、送金の前にもう一度直接話してください。」）。

## 危険シグナルへの注意文

以下の条件では、対応する注意文を結果にかかわらず表示する。

| 条件 | 注意文 |
| --- | --- |
| 依頼に「緊急」「今すぐ」が含まれる | 「『今すぐ』と急かすのは詐欺の典型的な手口です。」 |
| 送金先が初めての口座 | 「初めての送金先です。30 分の待ち時間の間に、もう一度考えてください。」 |
| 深夜（22 時から 6 時）の高額要求 | 「夜間の急なお金の話は、翌朝にもう一度確認することをおすすめします。」 |
| 応答なし・期限切れ | 「困ったときは警察相談専用電話 #9110 に相談できます。」 |

## 通知文言

- プッシュ通知に金額・送金先を含めない（ロック画面での漏えい防止）。「確認のお願いが届いています」とのみ表示する。
- 通知から開いた先で全文を表示する。

## マーケティング・ストア掲載文の禁止表現

- 「詐欺を 100% 防ぐ」「完全に安全」「本人かどうかが分かる」。
- 「AI が偽物を見破る」（本サービスは真偽判定を行わない）。
- 保証外の脅威（脅迫・端末乗っ取り・家族内不正）を防げるかのような表現。

推奨する表現: 「お金の話は、声ではなく家族の登録端末で確かめる。」
