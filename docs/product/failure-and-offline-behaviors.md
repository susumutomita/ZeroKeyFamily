# 失敗時・通信断時の挙動一覧

通信断・エラー・タイムアウト時の挙動の正本。安全側に倒す原則を定義し、状況ごとの表示と内部挙動を列挙する。

正本 Issue: https://github.com/susumutomita/ZeroKeyFamily/issues/3

## 原則（fail-safe）

1. 不明な状態を安心情報として表示しない。検証が完了していない限り「確認済み」を表示しない。
2. 通信断・エラー時の既定の案内は常に「お金を送らないでください」とする。
3. 部分的な成功を成功として表示しない。署名の取得に成功しても検証が未完了なら「未確認」である。
4. 再試行は自動で行い、ユーザーに技術的な判断（再送するか等）を求めない。再試行中であることのみ表示する。
5. すべての失敗画面に「困ったとき（緊急停止・相談）」への導線を置く。

## 状況別挙動一覧

### 確認要求の作成・送信時

| 状況 | 画面表示 | 内部挙動 |
| --- | --- | --- |
| 作成中に通信断 | 「インターネットに接続できていません。接続後に送信できます。」 | 下書きを端末内に保存し、接続回復後に明示操作で送信する（自動送信しない）。 |
| 送信後、サーバー未達 | 「送信できませんでした。再試行しています。」 | 指数バックオフで再送する。nonce は同一とし、二重送信を防ぐ。 |
| 送信成功、相手端末へ未配達 | 「太郎さんの端末にまだ届いていません。」 | 配達状態を表示する。期限到来で期限切れに確定する。 |
| 必須項目（金額・送金先・理由）の欠落 | 送信ボタンを無効化し、欠落項目を明示する。 | 作成 API は欠落要求を拒否する（クライアント検証に依存しない）。 |

### 確認要求の受信・応答時

| 状況 | 画面表示 | 内部挙動 |
| --- | --- | --- |
| 受信側が通信断 | 接続回復後に通知する。期限超過分は「期限切れのお願いがありました」と表示する。 | 期限切れの要求への署名を端末側で拒否する。 |
| 署名生成後、送信前に通信断 | 「回答を送信しています。」 | 署名を端末内に保持し、接続回復後に送信する。期限超過時は破棄し、双方に期限切れを表示する。 |
| 生体認証の失敗 | OS 標準のリトライ案内に従う。 | 規定回数失敗でパスコードへフォールバックする。署名は認証成功まで生成しない。 |
| 受信内容の改ざん検出 | 「このお願いは安全に表示できません。」 | 要求を無効化し、依頼者側に「検証失敗」を表示する。 |

### 検証・結果表示時

| 状況 | 画面表示 | 内部挙動 |
| --- | --- | --- |
| 署名の検証失敗 | 「応答の検証に失敗しました。安全のため、承認として扱いません。」 | 承認と区別した「検証失敗」状態に確定する。監査ログに記録する。 |
| 失効済み鍵による署名 | 「この端末は使えなくなっています。承認として扱いません。」 | 検証で拒否し、失効後署名として監査ログに記録する。 |
| 期限・nonce の不一致 | 「このお願いはすでに無効です。」 | リプレイとして拒否し、監査ログに記録する。 |
| 結果取得中に通信断 | 「確認の状態がわかりません。確認できるまで、お金を送らないでください。」 | 端末キャッシュの古い状態を「最新」として表示しない。取得時刻を併記する。 |

### 登録・失効・復旧時

| 状況 | 画面表示 | 内部挙動 |
| --- | --- | --- |
| QR 読み取り中の通信断 | 「接続できないため登録を進められません。」 | 片側のみ登録された中間状態を作らない（相互確認の完了でのみ確定する）。 |
| 失効申請中の通信断 | 「申請を送信しています。送信できるまで端末は止まりません。」と明示する。 | 失効はサーバー受理時点で有効化する。受理前であることを隠さない。 |
| 緊急停止の発動中に通信断 | 「停止の依頼を送信しています。送信できるまで停止は有効になりません。電話での連絡もしてください。」 | 接続回復後に最優先で送信する。代替手段（家族への電話・#9110）を画面に表示する。 |
| サーバー障害（全面） | 「現在サービスを利用できません。お金の確認はサービスの回復を待つか、直接会って確かめてください。」 | ステータスページへ誘導する。障害中の要求・承認は受け付けない（縮退して承認だけ通すことをしない）。 |

## タイムアウトの既定値

| 操作 | 既定値 | 備考 |
| --- | --- | --- |
| 確認要求の回答期限 | 30 分 | 作成時に 10 分から 24 時間で変更可。 |
| 送信再試行 | 最大 5 回（指数バックオフ） | 以後は手動再送導線を表示する。 |
| 状態表示のキャッシュ許容 | 60 秒 | 超過時は「最新の情報を取得できません」を併記する。 |

## 実装欠陥として扱う挙動

以下が発生した場合はバグ修正ではなくリリースブロッカーとして扱う。

- 「応答なし」「期限切れ」「検証失敗」「通信断」のいずれかが「確認済み」と同じ視覚表現・文言で表示された。
- 失効済み鍵・期限切れ要求・nonce 不一致の署名が「確認済み」になった。
- 通信断中にキャッシュ由来の「確認済み」が取得時刻なしで表示された。
