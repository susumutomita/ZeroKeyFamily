# 高齢者ユーザビリティテスト計画

高齢者を対象にしたユーザビリティテストの計画の正本。「確認済み」の意味の誤解と「応答なし」の誤認を最重要リスクとして検証する。

正本 Issue: https://github.com/susumutomita/ZeroKeyFamily/issues/3

## 目的

1. 高齢者が補助なしで確認要求の受信・承認・拒否を完了できるかを測定する。
2. 「確認済み」「応答なし」「拒否」「期限切れ」の意味を正しく理解できるかを測定する。
3. 詐欺を模した圧力下（時間制限・緊急の演出）でも、安全側の行動（送金しない・相談する）を選べるかを観察する。

## 参加者

| 区分 | 人数 | 条件 |
| --- | --- | --- |
| 高齢者（主対象） | 8 名以上 | 65 歳以上。スマートフォン利用歴 1 年以上 4 名、1 年未満 4 名。 |
| 高齢者（補助対象） | 4 名以上 | 75 歳以上。文字拡大・読み上げ等のアクセシビリティ機能利用者を含める。 |
| 家族側（副対象） | 4 名以上 | 上記参加者の家族役。30 歳から 60 歳。 |

- 募集時に視覚・聴覚・運動機能の多様性を確保する。
- 倫理配慮: 詐欺を模したシナリオは事前同意とデブリーフィングを必須にし、参加者が実際の不安を抱えないよう終了時に種明かしと相談先の案内を行う。

## テスト形式

- 1 名あたり 60 分の対面モデレートテスト。思考発話法と事後インタビューを併用する。
- 実機（参加者の普段の持ち方・文字サイズ設定）で実施する。
- 各タスクの後に理解度確認の質問を行う。

## タスクとシナリオ

| 番号 | タスク | 成功条件 |
| --- | --- | --- |
| T1 | 家族からの確認のお願いを開き、内容を読み、承認する | 補助なしで承認を完了し、金額・送金先を口頭で再現できる。 |
| T2 | 身に覚えのない内容のお願いを拒否する | 拒否を選択できる。承認との操作差（拒否の方が軽い）に気づく。 |
| T3 | 「息子」を名乗る電話（録音演技）で送金を求められ、アプリで確認する | 確認要求を作成・送信できる。金額・送金先・理由を入力できる。 |
| T4 | T3 の続きで、相手が応答しない（応答なし画面） | 「確認できていない」と正しく言語化し、「送金しない」を選ぶ。 |
| T5 | 「確認済み」画面を見て意味を説明する | 「太郎さんの端末が同意した」と説明でき、「相手の声が本物と証明された」と答えない。 |
| T6 | 困ったときメニューから緊急停止を発動する | 2 タップ以内の導線で 60 秒以内に発動できる。 |
| T7 | （家族側）高額のお願いに第 2 承認者として応答する | 待機時間の意味を理解し、待機中の取り消し方法を見つけられる。 |

## 測定指標と合格基準

| 指標 | 合格基準 |
| --- | --- |
| タスク完了率（T1 から T6、補助なし） | 80% 以上。 |
| 「確認済み」の意味の誤解率（T5） | 0%。1 名でも「本人の声と証明された」等と回答したら文言・画面を改修して再テストする。 |
| 「応答なし」を安心情報と誤認した率（T4） | 0%。同上。 |
| T4 で送金しない選択をした率 | 100%。 |
| 緊急停止の発動時間（T6） | 中央値 60 秒以内。 |
| 主観評価（SUS） | 平均 70 点以上。 |

誤解率 0% を合格基準とする理由: 誤解はそのまま被害につながるため、発生率を許容するのではなく、発生した誤解の原因を特定して改修するサイクルを基準に組み込む。

## 実施時期と再テスト

- 第 1 回: ワイヤーフレーム段階のプロトタイプで実施する（実装着手前）。
- 第 2 回: ベータ版で同一タスクを再実施する。
- 合格基準を満たさない項目がある限り、商用リリースのゲート（[ロードマップ](./roadmap.md)）を通過できない。

- 発見された問題の一覧（深刻度付き）と、文言・画面への反映先。
