# スコープと非目標

初期商用リリースに含むもの・含まないもの・恒久的に行わないものの正本。境界の変更は ADR を伴う。

正本 Issue: https://github.com/susumutomita/ZeroKeyFamily/issues/2

## 初期商用リリース（Phase 1）に含むもの

### アプリ・プラットフォーム

- iOS / Android ネイティブアプリ。App Store / Google Play で配布する。
- 端末鍵の生成と保管（Apple Secure Enclave / Android Keystore・StrongBox）。

### 家族登録

- 初回登録・本人確認・端末鍵生成。
- 家族招待（対面 QR 登録・遠隔登録）。遠隔登録には待機時間と多経路確認を課す。

### 確認要求

- 確認要求の作成・受信・承認・拒否・期限切れ。
- 署名検証と検証結果の表示（確認済み・拒否・期限切れ・応答なし・検証失敗の区別）。
- 高リスク操作（高額・緊急表示・送金先変更）の追加確認。複数人承認と待機時間。

### 安全機構

- 端末紛失時の失効、機種変更時の復旧。
- 家族からの離脱、死亡・関係解消時の Trust Circle 整理。
- 誤承認・脅迫・詐欺疑い時の緊急停止。

### 運用

- 監視・SLO・バックアップ・インシデント対応・サポート窓口（詳細は [ロードマップ](./roadmap.md) のリリースゲート）。

## 初期リリースに含まないもの（将来構想）

以下は設計上の拡張余地として考慮するが、Phase 1 では実装しない。導入には実用性評価と ADR を要する。

| 項目 | 状態 | 導入条件 |
| --- | --- | --- |
| ZKP による Trust Circle membership の選択的開示 | 将来構想 | プロトコル設計の独立レビューと性能評価。 |
| MPC による鍵分散・閾値署名 | 将来構想 | 標準・監査済みライブラリの成熟。 |
| FHE の活用 | 将来構想 | 実用性評価を経て本番導入可否を判断する。 |
| ブロックチェーン Trust Registry | 将来構想 | 個人情報を置かない構成で、集中型登録簿に対する必要性が実証されること。 |
| 金融機関・決済 API との連携 | 将来構想 | Phase 1 の検証実績と提携先の合意。 |
| 音声・ビデオ通話機能の内蔵 | 対象外 | 通話は既存手段を使う。本サービスは確認のみを担う。 |
| Web ブラウザ版・デスクトップ版 | 将来構想 | セキュアハードウェアに相当する鍵保管の確保。 |

## 非目標（恒久）

以下はロードマップ上の優先度の問題ではなく、プロダクトの原則として行わない。

- AI 生成音声・映像の真偽判定。生体・声・顔の「本物判定」を信頼の根にしない。
- 秘密鍵のサーバーへの平文保管、およびサーバー側での署名代行。
- 個人情報・家族関係・確認履歴のパブリックチェーンへの保存。
- 暗号方式の自作。標準・監査済みライブラリのみ利用する。
- 通話内容の録音・解析・保存。
- 法律上の親族関係や公的な身元の証明。

## 高リスク操作のしきい値（Phase 1 初期値）

| 条件 | 追加確認 |
| --- | --- |
| 金額が 10 万円以上 | 第 2 承認者の署名を必須にする。 |
| 送金先が過去に承認実績のない口座 | 30 分の待機時間を課し、待機中の取り消しを可能にする。 |
| 依頼に「緊急」「今すぐ」の指定がある | 緊急表示を理由として待機時間を短縮しない。注意文を強調表示する。 |
| 金額・送金先・理由のいずれかが未入力 | 確認要求を作成できない（省略不可）。 |

しきい値は家族設定で厳しくできるが、初期値より緩くできるのは金額しきい値のみとし、送金先変更と未入力禁止は緩和不可とする。
