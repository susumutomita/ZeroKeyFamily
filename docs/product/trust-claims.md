# Trust Claims（信頼保証と限界）

ZeroKey Family がユーザーに何を保証し、何を保証しないかの正本。すべての画面文言・マーケティング表現・サポート回答は本文書に反してはならない。誤った安心感は暗号上の欠陥と同等に危険である。

正本 Issue: https://github.com/susumutomita/ZeroKeyFamily/issues/2

## 保証すること

1. 「確認済み」と表示した場合、対象メンバーの失効されていない登録端末の秘密鍵が、その確認要求の内容（対象・金額・送金先・理由・期限・nonce・依頼者）そのものに有効な署名を行ったことを保証する。
2. 署名は確認要求の全フィールド（承認者が画面で読む理由テキストを含む）を束縛する。承認済みの署名を、金額・送金先・理由・対象が異なる別の依頼の証拠として再利用できない。
3. nonce と期限により、過去の署名のリプレイを検証で拒否する。
4. 失効済みの端末鍵による署名を「確認済み」として表示しない。
5. 秘密鍵はサーバーへ平文で預けない。サーバー運営者・侵入者は登録端末の署名を偽造できない。
6. 暗号方式は自作せず、標準・監査済みライブラリを利用する。

## 保証しないこと

1. 脅迫下の承認（duress）。署名は「登録端末が操作されたこと」を示すのみで、署名者が自由意思であったことを示さない。緊急停止と高リスク操作の待機時間で被害を緩和するが、検出は保証しない。
2. 端末乗っ取り。OS レベルで侵害された端末や、ロック解除手段を奪われた端末からの署名は防げない。失効による事後対応のみ提供する。
3. 家族内不正。Trust Circle のメンバー自身による悪意の承認・依頼は防げない。
4. 登録時の身元。家族登録は招待と相互確認に基づく。対面 QR 登録は遠隔登録より強いが、いずれも公的な身元証明ではない。
5. 依頼内容の正当性。「確認済み」は依頼が安全・合法・賢明であることを意味しない。
6. 声・映像の真偽判定。ZeroKey Family は通話内容を検査しない。

## 信頼の根にしないもの

以下を本人性・家族関係の根拠として使う実装・文言・販促を禁止する。

- 声（声紋・話し方を含む）。
- 映像・顔。
- 電話番号・発信者表示。
- 表示名・プロフィール画像。
- メールアドレス・SNS アカウント。

これらは利便性のための表示情報として使ってよいが、検証結果に影響させてはならない。

## 限定保証の整理

| 脅威 | 保証の範囲 | 緩和策 |
| --- | --- | --- |
| AI 音声・映像によるなりすまし | 保証する（署名がなければ「確認済み」にならない） | 確認要求フローそのもの |
| 署名の流用・リプレイ | 保証する | 内容束縛・nonce・期限 |
| サーバー侵害による署名偽造 | 保証する | 鍵の端末内保管 |
| 脅迫下の承認 | 保証しない（限定緩和） | 高リスク操作の待機時間・複数人承認・緊急停止 |
| 端末乗っ取り・ロック解除の強奪 | 保証しない（限定緩和） | 即時失効・家族からの失効申請 |
| 家族内不正 | 保証しない | 履歴の透明性・複数人承認 |
| 登録時のなりすまし | 限定保証 | 対面 QR 登録の推奨・遠隔登録時の待機時間と多経路確認 |

## 「確認済み」の誤解を防ぐ要求

ユーザーが「確認済み」を「相手は本人で安全」と誤解しないために、以下を製品要求とする。文言の具体例は [安全文言ガイド](./safety-copy-guide.md) を正本とする。

- 「確認済み」の表示には、何が確認されたか（誰の登録端末が・どの依頼に署名したか）を常に併記する。
- 「本人です」「安全です」という断定表現を全画面・全販促で禁止する。
- 「応答なし」「期限切れ」「検証失敗」を、承認とも拒否とも視覚的・文言的に混同しない形で表示する。応答がないことを本人確認の成功として扱わない。
- 高リスク操作の確認結果には、脅迫・誤承認の可能性に触れる注意文と緊急停止への導線を併記する。

## マーケティング表現のレビュー

- すべての販促物・ストア掲載文・プレスリリースは、公開前に本文書との整合レビューを通す。
- 「詐欺を防ぐ」「100% 安全」など、保証しない範囲を保証するかのような表現を禁止する。「依頼内容への家族の署名を検証する」という事実ベースの表現を使う。
